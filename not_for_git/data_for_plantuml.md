Список сущностей для Шага 1, собранный из ТЗ FitAI (привязка к FR и US — чтобы на защите показать трассировку, это прямо критерий приёмки ЛР №2).

## 1. Входные данные (что модуль получает)

| Сущность | Состав | Источник в ТЗ |
| --- | --- | --- |
| `UserProfile` | возраст, пол, рост, вес, уровень подготовки | FR-01 |
| `UserGoal` | цель (похудение / поддержание / масса), срок | FR-01 |
| `TrainingHistory` | выполненные тренировки: упражнение, веса, повторы, подходы, дата | FR-03, US-02 |
| `NutritionLog` | приёмы пищи: блюдо, граммовки, КБЖУ, время | US-03, FR-08 |
| `BodyWeightHistory` | динамика веса по датам | FR-03 |
| `WorkoutPlan` (текущий) | план на сегодня / текущий микроцикл | US-01 |

Все это — **сырые данные, без обработки**. Нормализация/очистка — уже процесс (см. раздел 3).

## 2. Выходные данные (что модуль отдаёт)

| Сущность | Состав | Источник в ТЗ |
| --- | --- | --- |
| `WorkoutPlan` (рекомендованный) | упражнения, подходы, веса, объём, интенсивность | FR-06, FR-07, US-01 |
| `NutritionRecommendation` | калорийность, БЖУ (граммы), корректировки под цикл | FR-08, US-03 |
| `OvertrainingAlert` | признак перегрузки + рекомендация отдыха/разгрузки | FR-09, US-05 |
| `ProModeSuggestion` | предложение перехода в «Режим Профи» | US-06 |
| `RecommendationExplanation` | текстовое объяснение + ключевые факторы | FR-10, FR-14 |
| `InferenceMetadata` | версия модели, время расчёта | FR-13 |

Важно: FitAI **не решает**, показывать ли что-то пользователю, и не начисляет XP — это границы системы из раздела 3 ТЗ. Модуль только формирует рекомендацию и передаёт её наружу.

## 3. Процессы (что происходит внутри модуля)

| Процесс | Вход → выход | Источник в ТЗ |
| --- | --- | --- |
| Валидация данных | сырые данные → валидированные / признак неполноты | FR-15, US-07 |
| Классификация уровня | профиль + история → уровень подготовки | FR-02 |
| Построение признаков | история тренировок/питания/веса → вектор признаков `float[]` | FR-03 |
| Инференс | вектор признаков → выход модели | FR-05 |
| Принятие решения | выход модели + контекст → нагрузка/план | FR-06, FR-07 |
| Расчёт питания | профиль + цель + лог питания → КБЖУ | FR-08 |
| Детектирование перегрузки | история + текущие показатели → алерт / ∅ | FR-09 |
| Fallback-логика | (нет модели / нет данных) → рекомендация по правилам | FR-11, US-07 |
| Форматирование | рекомендация → текст + объяснение | FR-10, FR-14 |
| Передача результата | рекомендация → FitCalc по REST | FR-12 |

Проверьте себя правилом SRP: каждый процесс — один класс с одной причиной для изменения (кстати, это сразу каркас для диаграммы Шага 2 — интерфейсы почти взаимно однозначно ложатся на эти процессы).

## 4. Внешние зависимости (что модуль не контролирует)

| Зависимость | Роль |
| --- | --- |
| ONNX-модель (файл `.onnx`) | «чёрный ящик»: вход — тензор признаков, выход — вероятности/значения. Как училась — неважно |
| ONNX Runtime (`onnxruntime`) | нативная библиотека инференса, требует управления ресурсами (в Python — `InferenceSession.close()` / контекстный менеджер) |
| FitCalc (Python/FastAPI) | внешнее приложение: регистрация, хранение данных, XP, рейтинги; FitAI обменивается с ним по REST |
| PostgreSQL | (опционально) если решите не дёргать FitCalc за данными, а читать напрямую — отметьте это как сознательное решение, иначе на защите спросят |
