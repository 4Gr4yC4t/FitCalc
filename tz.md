Основное приложение FitCalc отвечает за регистрацию, хранение данных, питание, тренировки, XP и аналитику. Предметом ЛР №2 является отдельный модуль FitAI, который анализирует данные пользователя и формирует персональные рекомендации.

2. Назначение и цели

FitAI предназначен для автоматической персонализации тренировочного процесса и питания пользователя.

Модуль должен:

· определять уровень подготовки пользователя;
· подбирать нагрузку с учётом истории тренировок;
· адаптировать план при пропусках и снижении результатов;
· анализировать связь питания и тренировочного прогресса;
· рекомендовать изменение калорийности и КБЖУ;
· выявлять признаки перегрузки;
· предлагать переход из режима новичка в режим Профи.

Цель создания модуля — уменьшить объём ручной настройки тренировок и предоставить пользователю понятные рекомендации на основе накопленных данных.

3. Границы системы

В состав FitAI входят:

· обработка профиля пользователя;
· анализ тренировок, веса и питания;
· расчёт признаков для модели;
· запуск ONNX-модели;
· принятие решения по результату инференса;
· генерация рекомендации;
· передача результата в FitCalc.

В состав FitAI не входят:

· регистрация и авторизация пользователей;
· хранение пользовательских данных;
· отображение веб-интерфейса;
· ведение базы продуктов;
· начисление XP;
· реализация рейтингов и лиг;
· резервное копирование базы данных.

Эти функции выполняются внешним приложением FitCalc.

6. Архитектура модуля

Основные интерфейсы:

```csharp
public interface IAIController
{
    Task<FitnessRecommendation> BuildRecommendationAsync(
        FitnessUserContext context,
        CancellationToken cancellationToken);
}
```

```csharp
public interface IInferenceService
{
    Task<InferenceResult> RunAsync(
        float[] features,
        CancellationToken cancellationToken);
}
```

```csharp
public interface IWorkoutDecisionMaker
{
    WorkoutPlan CreatePlan(
        FitnessUserContext context,
        InferenceResult inferenceResult);
}
```

Основные классы:

· FitAIController;
· FitnessDataProvider;
· FeatureBuilder;
· NeuralNetworkInferenceService;
· UserLevelClassifier;
· WorkoutDecisionMaker;
· NutritionRecommendationService;
· OvertrainingDetector;
· RuleBasedFallback;
· FitCalcApiClient;
· RecommendationFormatter.

Принцип разделения ответственности:

· FeatureBuilder не принимает решений;
· NeuralNetworkInferenceService только запускает модель;
· DecisionMaker интерпретирует результат;
· FitCalcApiClient отвечает только за обмен данными;
· RuleBasedFallback используется при недоступности модели.

10. Критерии приёмки

Модуль считается готовым, если:

· все User Stories связаны с функциональными требованиями;
· модель загружается из ONNX-файла;
· рекомендация формируется не более чем за 500 мс;
· инференс не блокирует главный поток;
· при сбое модели запускается fallback;
· покрытие бизнес-логики тестами составляет не менее 80%;
· API FitCalc корректно принимает рекомендации;
· для каждой рекомендации передаётся причина её формирования.
